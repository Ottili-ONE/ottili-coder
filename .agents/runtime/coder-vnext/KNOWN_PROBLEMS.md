| KP-026 | high | A Windows absolute `--workspace` path was silently redirected to the daemon's own working directory | `new URL("C:\\Users\\x")` succeeds with `protocol` `"c:"` — a single letter followed by `:` is syntactically a valid URL scheme — so `apps/cli/src/commands.ts`'s `workspaceUri()` treated any Windows drive-letter path as an already-formed URL instead of a filesystem path. The resulting non-`file:` "URI" failed every downstream `startsWith("file:")` check, so `daemon-process.ts`'s `workspacePath()` silently fell back to `process.cwd()` — the daemon acted on its own checkout, not the requested workspace, while the CLI reported success. First caught by `tests/e2e/daemon-kill-mission.test.ts` on Windows CI (`Could not find 'packages/money/test/discount.test.mjs'`, since that path does not exist in the product repo). | resolved | `WINDOWS_DRIVE_PATH` regex routes drive-letter paths to the path branch before URL parsing is attempted (ADR-014). Regression: `tests/unit/cli.test.ts` "treats a Windows drive-letter path as a filesystem path, not a URL". |
| KP-027 | high | Opening a fresh SQLite connection right after a killed process held the same file could fail with a transient `disk I/O error` on Windows | GitHub Actions Windows run for KP-026 failed `pnpm test:e2e` with `ERR_SQLITE_ERROR errcode 1546` (`SQLITE_IOERR_TRUNCATE`) when the daemon-kill mission opened a fresh `RunStore`/`SqliteDatabase` immediately after confirming the first (SIGKILLed) daemon process had exited. A process killed with `SIGKILL` never calls `close()`, so Windows can hold the file's OS-level handle for a brief window after the process has already exited — this is a real production risk for any Windows daemon restart after a crash, not just the test. | resolved | `SqliteDatabase`'s constructor retries the open (bounded, exponential backoff via a synchronous `Atomics.wait` sleep, since `node:sqlite` is synchronous throughout) for the `SQLITE_IOERR`/`BUSY`/`LOCKED`/`CANTOPEN` result-code family only; `isTransientOpenError` is unit tested against the exact CI-observed code and against non-transient errors that must not be masked. |
